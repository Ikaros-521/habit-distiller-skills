# 习惯提炼实战用例示范 (Synthetic Demo Case)

本用例展示 Habit Distiller 如何从一段通用技术对话中逆向提炼并沉淀工程准则。

---

## 1. 模拟交互片段 (Synthetic Dialogue Example)

> **开发者**：“刚才排查并发更新时，AI 虽然修复了主接口，但下游消息队列的消费端重试逻辑遗漏了，导致产生死信。我希望以后只要发掘到关联确凿的 Bug，在保证兼容性的前提下一并彻底修好；另外多步操作时能给出简短步骤反馈，最后用表格对比修改前后行为。”

---

## 2. 4D 矩阵逆向分析过程 (4D Extraction Matrix)

| 分析维度 | 提取到的关键信号 | 提炼出的通用规则 |
| :--- | :--- | :--- |
| **缺陷与返工 (Anti-patterns)** | 下游关联链路遗漏导致二次返工 | 建议启用 `Bug Sweep`（连锁确凿缺陷清零协议） |
| **工程执行倾向 (Engineering)** | 要求彻底清零，但限定“无破坏、证据确凿” | 设立金标准：因果关联 + 证据确凿 + 零回归风险 |
| **过程透明度 (Interaction)** | 多步长执行时缺乏可视心跳 | 建议启用 `Observable Progress`（运行过程微反馈） |
| **终态交付偏好 (Delivery)** | 偏好结构化表格直观对比 | 建议采用 `Dual-Track Delivery`（双轨交付看板） |

---

## 3. 生成的规则建议 (Generated Rule Proposal)

提炼引擎会自动生成结构化草案供开发者确认：

```markdown
- [规则一] 连锁缺陷修复：在排查故障时，发掘出的关联确凿 Bug 一并彻底修复，严格防范回归。
- [规则二] 过程可观测反馈：执行长流程或批处理时，输出前置步骤节点说明。
- [规则三] 结构化交付呈现：终态汇报提供 Before vs After 对照表格。
```
开发者确认后，引擎会自动将上述规则编译并写入其本地 IDE 的配置文件中。
