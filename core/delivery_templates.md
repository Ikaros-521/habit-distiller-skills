# 终态高可读性交付看板与合规契约规范 (Delivery Protocol)

## 1. 核心理念与防遗漏机制

- **痛点破解**：如果仅让大模型“内心默念自审”，在大模型注意力漂移时，**自审逻辑本身极易被遗忘**。
- **结构化输出契约 (Structural Output Contract)**：
  将习惯合规自查直接**物理固化为终态看板的必填字段**。模型在生成 Markdown 表格时，为了补齐单元格，必须强制触发注意力机制核验指标，从而保证 100% 履约，彻底避免遗漏。

---

## 2. 深度任务标准交付看板模板 (Dashboard Template)

AI 在完成复杂工程交付（Deep Path）时，必须输出以下结构化看板：

```markdown
### 📊 任务执行与交付看板

#### 1. 核心结论与履约状态
| 指标维度 | 履约状态 | 说明与实证 |
| :--- | :--- | :--- |
| **核心任务目标** | 🎯 [完全达成 / 局部完成] | [简明成果说明] |
| **习惯契约核验** | 🛡️ [连带缺陷清零 / 过程已反馈] | [已核查关联链路，无衍生 Bug / 无破坏既有功能] |
| **回归测试状态** | ✅ [通过 / 需人工自测] | [测试指令与覆盖项说明] |

#### 2. 代码与功能变更明细 (Before vs After)
| 模块 / 关联文件 | 修改前行为 | 修改后行为 | 变更类型 |
| :--- | :--- | :--- | :--- |
| `path/to/file1` | 原先存在空指针隐患 | 增加安全校验与兜底 | 🐛 主缺陷修复 |
| `path/to/file2` | 连锁下游未做异常捕获 | 补齐异常链与状态回滚 | 🔍 连带确凿缺陷清零 |

#### 3. 连锁确凿缺陷排查记录 (若有发掘)
- **缺陷 A**：[位置] - [复现与判定依据] - [无害化修复措施]

#### 4. 后续跟进与提示 (Next Steps)
- [x] 代码已编译/语法通过
- [ ] 建议用户本地运行业务自测: `npm test` 或相关验证
```

---

## 3. 极速直通微任务免除规则

对于单行命令查询、语法释义等微任务（Fast Path），自动免除上述看板，单行直出干净答案，以保证极致敏捷。
