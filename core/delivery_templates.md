# 终态高可读性交付看板与合规契约规范 (Delivery Protocol v2.6)

## 1. 核心理念与防阳奉阴违机制

- **痛点破解**：如果仅让大模型“内心默念自审”，在大模型注意力漂移时，**自审逻辑本身极易被遗忘**；更严重的是，模型极易产生**“阳奉阴违”**——明明未实际排查代码，却在看板里打虚假勾。
- **结构化输出契约 + 事实证据探针 (Fact-Based Proof Anchor)**：
  将习惯合规自查物理固化为终态看板的必填字段，且**强制要求提供真实查验实据**（查验了哪些文件/行号、测试指令是什么、或者未发现次生 Bug 的逻辑证据）。**无证据一律视为未履约**，彻底杜绝形式主义打勾。

---

## 2. 深度任务标准交付看板模板 (Dashboard Template)

AI 在完成复杂工程交付（Deep Path）时，必须输出以下结构化看板：

```markdown
### 📊 任务执行与交付看板

#### 1. 核心结论与履约事实证据
| 指标维度 | 履约状态 | 事实证据 (严禁空洞套话，必须有实据) |
| :--- | :--- | :--- |
| **核心任务目标** | 🎯 [完全达成 / 局部完成] | [简明成果与验证结论] |
| **习惯契约核验** | 🛡️ [连带清零 / 过程反馈] | **真实证据**：[列出排查的关联文件:行号/调用链，证实为何无次生缺陷；若无衍生缺陷，列出判定理由] |
| **回归测试状态** | ✅ [通过 / 需人工自测] | [具体测试指令，如: `npm test` 或编译命令及输出结果] |

#### 2. 代码与功能变更明细 (Before vs After)
| 模块 / 关联文件 | 修改前行为 | 修改后行为 | 变更类型 |
| :--- | :--- | :--- | :--- |
| `path/to/file1` | 原先存在空指针隐患 | 增加安全校验与兜底 | 🐛 主缺陷修复 |
| `path/to/file2` | 连锁下游未做异常捕获 | 补齐异常链与状态回滚 | 🔍 连带确凿缺陷清零 |

#### 3. 连锁确凿缺陷排查记录 (若有发掘)
- **连带缺陷 A**：[位置] - [复现与判定依据] - [无害化修复措施]
- *(若无连带缺陷)*：已全面扫描 `[关联模块/文件]` 的调用方，参数边界均受防线保护，未见次生暗坑。

#### 4. 后续跟进与提示 (Next Steps)
- [x] 代码已编译/语法通过
- [ ] 建议用户本地运行业务自测: `npm test` 或相关验证
```

## 3. 极速直通微任务免除规则

对于单行命令查询、语法释义等微任务（Fast Path），自动免除上述看板，单行直出干净答案，以保证极致敏捷。
