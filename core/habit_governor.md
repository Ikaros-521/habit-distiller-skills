# Habit Governor: 习惯生命周期治理与全景防熵增引擎 (v2.5)

本文档定义了 Habit Distiller 如何在提炼与运行个人习惯时进行**单条习惯靶向删除、多套习惯档案无缝切换、单域 1+3 聚类浓缩、主观虚词反模糊转译、知行背离智能自愈与冲突仲裁**的标准作业程序（SOP）。

## 2. 档案与生命周期管理细则

### 机制一：多套习惯档案无缝切换 (Multi-Profile Switcher)
- **第一性原理**：开发者在不同场景下的要求天然不同（例如：商业企业项目需要严格企业合规，个人开源摸鱼追求极简轻快，开源公开项目需要规范双语文档）。
- **文件拓扑架构**：
  ```text
  ~/.habit-distiller/
  ├── habits.md                  # 当前活跃生效的单一真相源
  ├── habits.md.bak              # 写前物理容灾镜像
  └── profiles/                  # 多套独立档案存储库
      ├── default.md             # 默认通用底座
      ├── open-source.md         # 开源项目与双语文档档案
      ├── work.md                # 商业项目合规严谨档案
      └── personal.md            # 个人极速摸鱼档案
  ```
- **自然语言切换指令**：
  - 用户说：“`切换习惯档案 work`” 或 “`使用开源档案`”：
    1. AI 先将当前活跃的 `habits.md` 自动保存回对应的原档案（防丢失）；
    2. 将 `profiles/<profile_name>.md` 物理原子覆盖至 `habits.md`；
    3. 提示：*“✅ 已成功无缝切换至【work】档案，当前所有会话已即刻生效。”*
  - 用户说：“`查看习惯档案`”：列出本机 `~/.habit-distiller/profiles/` 下所有档案列表并标明当前活跃项。
  - 用户说：“`保存当前习惯为 [档案名]`”：将当前活跃真相源复制为新档案。

---

### 机制二：单条习惯定向精准注销/删除 (Targeted Deletion Protocol)
- **补齐 CRUD 闭环**：支持对单条特定规则的靶向拔除。
- **触发指令**：用户发送“删除习惯 [规则名/领域/序号]”或“注销双语文档习惯”。
- **执行流程**：
  1. AI 先执行写前物理镜像备份 `habits.md.bak`；
  2. 准确定位目标领域及对应条目，执行精准物理移除；
  3. 保留其余所有正常规则完好无损；
  4. 向用户输出确认卡片：
     > 🗑️ *“已为您注销习惯：【开源双语文档】。其余规则完好生效，并已同步生成备份镜像。”*

---

### 机制三：自然语言一键撤回 (Atomic Undo Protocol)
- **触发口令**：用户发送“撤回刚才的习惯更新”或“恢复上一版习惯”。
- **执行逻辑**：
  1. 检查是否存在 `~/.habit-distiller/habits.md.bak`；
  2. 物理原子替换回 `habits.md`；
  3. 输出确认：*“已为您安全撤回上一版更新，习惯已恢复至修改前的快照状态。”*

## 3. 提炼判定决策流与单域 1+3 浓缩

### 机制四：4-Way 提炼判定决策树
当提炼出新规则时，AI 严禁机械向下累加，必须通过 4 步决策树进行收敛：
1. **去重判别 (Dedup)**：语义重复或完全被已有规则包含 $\to$ 丢弃并不额外增加条目。
2. **版本覆盖 (Override)**：与既有规则发生冲突或演进 $\to$ 直接替换旧规则，更新版本戳。
3. **同类合并 (Merge)**：与既有规则属于同一维度 $\to$ 聚类提炼，收敛为一条更加普适的方法论。
4. **增量插槽 (Insert)**：完全属于新维度且全局规则条数 $< 8$ 条 $\to$ 插入至对应 Domain 插槽。

---

### 机制五：单域 1+3 聚类浓缩协议 (Per-Domain Anti-Bloat)
- **1+3 结构化收敛标准**：每个 Domain 内部**强制规范为“1 条核心行动纲领 + 最多 3 条边界约束指标”**：
  ```markdown
  ## [DOMAIN: DEFECT] 缺陷修复与防线规范
  - **核心行动纲领 (Core Directive)**：在排查或修复目标问题时，发掘出的关联确凿缺陷必须一并无破坏彻底修复。
  - **边界指标 (Boundaries)**：
    1. 必须有逻辑矛盾或报错事实证据，严禁风格主观臆断；
    2. 严格保持公开 API 契约不变，确保 0 回归；
    3. 修复方案必须提供复现与验证说明。
  ```
- **熔断机制**：当同一领域内拟新增第 4 条细则时，治理引擎**自动触发聚类浓缩**，将相似指标提炼合并，严禁列表无限向下无序扩张。
- **全局硬上限**：全局规则总量维持在 **5~8 条黄金法则**，彻底防止规则膨胀（Anti-Hermes）。

## 4. 人性化转译与知行合一治理

### 机制六：主观虚词反模糊转译与强制逃生通道 (Actionability Disambiguation)
- **痛点**：开发者输入非量化主观词（如“写得更有艺术感”、“逻辑更严谨一点”、“回复聪明一点”）。
- **转译与逃生两步法**：
  1. **建议转译反问**：AI 立足第一性原理，将其转译为具体工程指标向用户反问：
     > 💡 *“您提到的‘逻辑更严密’，推荐转译为以下可量化执行的工程指标：<br>① 对输入入参执行防御性判空与边界兜底；<br>② 关键调用链补充异常捕获回滚。<br>请问是否按上述指标沉淀？（若您希望原样保留原话，请直接回复‘强制写入’）”*
  2. **强制写入逃生 (Force-Write Escape)**：若用户明确回复“强制写入”或坚持原话，AI 立即尊重用户意志，不再反问阻拦，直接原样写入。

---

### 机制七：知行背离智能自愈提示与冲突仲裁 (Habit-Action Drift Arbitration)
- **痛点**：书面习惯写着“必须补单测”，但现实连续多次会话用户都在催促“别写单测了，直接出业务代码”。
- **自愈提示**：当检测到用户在实际对话中连续 3 次显式违背某条书面习惯时，AI 主动输出温和卡片：
  ```markdown
  ⚠️ 检测到现实操作与书面契约发生背离：
  - 书面契约：每次改动必须包含单元测试
  - 现实偏好：近期连续 3 次指示跳过单测，直接出业务代码

  请选择您的意图：
  [1] 仅近期任务临时跳过，仍保留书面契约（当前会话特例放行）
  [2] 修改书面契约：调整为“仅在核心模块强制单测，日常微任务免测”
  [3] 直接注销该条单测习惯
  ```

## 5. 开发者掌控与透明交互

### 机制八：一键习惯清单与状态计分卡 (Scorecard Command)
- **触发指令**：用户发送“查看我的习惯”、“查看习惯清单”、“习惯状态”或“list habits”。
- **输出规范**：AI 立即读取 `~/.habit-distiller/habits.md`，以 1 页精炼的**可视化计分卡表格**直接渲染呈现：
  ```markdown
  ### 📋 您的专属 AI 协同契约清单 (Habit Scorecard)

  | 领域插槽 (Domain) | 核心行动纲领 (Core Directive) | 作用域 (Scope) | 状态 |
  | :--- | :--- | :--- | :--- |
  | 🧠 **COGNITION** | 深度任务多想 1~2 步，推演隐性盲区与生命周期风险 | `global` | 🟢 活跃 |
  | 🛡️ **DEFECT** | 确凿关联缺陷顺藤摸瓜一并彻底修复，严格防回归 | `global` | 🟢 活跃 |
  | 📡 **PROGRESS** | 微任务极速直通秒出结果，重任务步骤心跳可视 | `global` | 🟢 活跃 |
  | 📊 **DELIVERY** | 终态采用结构化对比表看板与 Artifacts 呈现 | `global` | 🟢 活跃 |
  | 🌐 **DOCS** | 开源公开项目 README 默认中英双语、中文置顶 | `global` | 🟢 活跃 |
  | 🚫 **FORBIDDEN** | 严禁私加大型外部库、乱删注释、提交硬编码密钥 | `global` | 🛑 阻断级 |

  - 💡 单一真相源路径：`~/.habit-distiller/habits.md` (写前镜像自动备份有效)
  - 🔧 快捷操作：回复“切换习惯 [名称]”、“删除习惯 [名称]”或“撤回刚才的更新”。
  ```

---

### 机制九：缺失工具权限主动索权提示 (Missing Tool Permission Prompt)
- **准则**：严禁隐式猜测或假装调用工具。当某个习惯（如构建验证、终端执行）因当前环境未授予工具权限（如缺少 `run_command`）受阻时：
- **主动交互**：AI 必须直接向用户索权或引导本地执行：
  > ⚠️ *“遵从您的【连带缺陷验证】习惯需要执行构建测试，但当前窗口未授予终端工具权限。请授予终端权限，或由您在宿主机本地终端运行：`npm test`。”*

---

### 机制十：会话压缩留存快照 (Compaction Snapshot)
- **场景**：当会话经过多轮长对话执行 `/compact` 上下文压缩，或在阶段性里程碑总结时。
- **输出规范**：AI 必须在压缩摘要头部输出一份简明快照，便于用户随时审阅与修正：
  ```markdown
  📌 [当前生效习惯快照]
  - 核心契约：前瞻发散推演 | 连带缺陷清零 | 意图分级自适应(微任务直通) | 双轨交付看板 | 开源双语文档
  - 作用域状态：当前技术栈命中规则已按需挂载
  - 如需调整当前协同习惯，可直接输入：“调整习惯 [规则名]” 或 “查看习惯清单”
  ```

---

### 机制十一：手工编辑自愈保护 (Permissive Self-Healing)
- **手改自愈**：读取 `habits.md` 时若检测到用户手工追加的非结构化手写文本，系统**绝不报错拒绝或静默丢弃**；重新落盘时，AI 将自动将其规范化重组归入最贴切的 Domain 插槽中。
